这里维护随代码版本演进的说明。阅读顺序按任务选择，不需要通读所有参考资料。

| 要做什么 | 从这里开始 |
| --- | --- |
| 安装、运行和配置 Paw | [使用与配置](guides/usage.md) |
| 找到某项职责的源码 | [目录地图](architecture/layout.md) |
| 理解会话执行、恢复与工具调用 | [运行时职责](architecture/runtime.md) |
| 构建、测试或扩展功能 | [开发指南](guides/development.md) |

## 文档归属

- `architecture/`：当前架构、边界与长期决策。
- `guides/`：面向使用者和开发者的可执行指南。
- `reference/`：按包拆分的接口与行为参考；发生冲突时以当前源码及测试为准。
- `local/`：本机计划、调研和过程记录，默认不进入 Git。

仓库根的 `memory/` 也用于本地工作记录。不要让长期文档依赖这些目录中的文件才能读懂。完成的设计应将仍然有效的结论整理进 architecture，而不是把整份过程记录变成永久规范。

Git 忽略只影响未跟踪文件；已经被历史版本跟踪的本地记录不会自动解除跟踪。本次整理不重写 Git 历史，也不自动提交私人研究资料。
